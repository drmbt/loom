# On Nothing scene generator (Blender side of T1400b)

This is a procedural bpy generator for the On Nothing look study: a dark warehouse, five SUV-class
cars, a figure, a white cyc and a chrome title. It exports one GLB, which loom's
`src/projects/on-nothing/` renders. Plan and reference:
`docs/on-nothing-shots-plan-2026-09-27.md` and `docs/on-nothing-look-reference-2026-09-27.md`.
Every build product and every render goes under the gitignored `renders/on-nothing/`.

## Run

```bash
B=/Applications/Blender.app/Contents/MacOS/Blender
$B --background --factory-startup --python tools/blender/on-nothing/build.py -- \
   --out renders/on-nothing/build/on-nothing.glb \
   --human renders/on-nothing/assets/mpfb-male-casual.blend \
   [--preview renders/on-nothing/build/preview] [--title "On Nothing"] [--blend <path>]
```

- A build takes a few seconds. `--preview` writes workbench stills from every `shot.*` camera and
  four `dbg.*` framings; these check the geometry, not the look.
- Without `--human` the figure is the procedural mannequin (`figure.build`). It works, but it has far
  less fidelity.

Then render in loom (see `src/projects/on-nothing/render.ts`):

```bash
node --import ./src/tooling/alias-hooks.ts src/projects/on-nothing/render.ts -- --width 1920 --at 2
node --import ./src/tooling/alias-hooks.ts src/projects/on-nothing/render.ts -- --clip 4 --shots tableau --crt
```

## The human (CC0)

The figure is a MakeHuman body generated by MPFB 2.0.17, so it has realistic proportions and a rig,
and it is clothed. MakeHuman's core assets are CC0: "You do not need to pay anything, include any
copyright notices nor give attribution"
(https://static.makehumancommunity.org/about/license.html). The asset files used here say they were
"explicitly released as CC0 in september 2020". MPFB itself is GPL-3, but it is only the generator,
and none of its code ships in the model.

`mpfb_human.py` rebuilds `mpfb-male-casual.blend`. MPFB and the system assets are installed in an
isolated Blender user directory kept in `renders/on-nothing/assets/blender-user/`, so your own
Blender config is never touched:

```bash
BLENDER_USER_RESOURCES=$PWD/renders/on-nothing/assets/blender-user \
  $B --background --factory-startup --python tools/blender/on-nothing/mpfb_human.py -- renders/on-nothing/assets/mpfb-male-casual game_engine
```

If that directory is lost, rebuild it from `mpfb-2.0.17.zip`
(https://extensions.blender.org/add-ons/mpfb/) and `mh_system_assets_cc0.zip`
(https://files2.makehumancommunity.org/asset_packs/makehuman_system_assets/makehuman_system_assets_cc0.zip).
Both are kept in `renders/on-nothing/assets/`.

`figure.build_mpfb` appends the body and does the following:

- It bakes the shape keys and the modifiers at rest, including MPFB's masks that hide the body under
  the clothes.
- It drops the eyebrows, the eyelashes and the hair, because loom draws no alpha cards and a beanie
  covers the head.
- It maps MPFB's materials onto ours.
- It subdivides once.
- It folds the 53 game-engine bones onto the 19 bones of `figure.BONES`: fingers go into the hand,
  the ball into the foot, spine_01 and spine_02 into the spine.
- It fits the beanie, the sunglasses, the chain and the bracelet to the measured head, eyes, neck
  and chest.

## Skinning

The figure exports as a real glTF skin (T1401b). The body is bound to the armature `fig.rig`,
which has the 19 bones of `figure.BONES`, and the exporter runs with `export_skins=True` and four
influences. loom's decoder reads JOINTS_0/WEIGHTS_0 and the joint table (name, parent, rest head),
and the figure's Mesh File In publishes `joints` and `weights` per vertex. A vertex that no bone
weights takes its nearest bone, so no vertex is left behind when a limb turns.

`src/projects/on-nothing/skin-kernel.ts` poses the figure from per-bone knobs. The figure stands at
the origin facing −Y (glTF +Z), in the rest A-pose.

## Contract loom reads

- **Areas:** every mesh is named `<area>.<name>`. The areas are `wh` (warehouse), `car`, `title`,
  `fig` and `cyc`, and loom loads one Mesh File In per area.
- **Material class:** each material's `loom_heat` extra carries its CLASS CODE ÷ 64 (see
  `mats.py`), and loom's surface shader draws by class. Nothing here is hot.
- **Cameras:** `shot.tableau`, `shot.title`, `shot.quad` and `shot.cyc` are exported at 1920×818
  (2.35:1), and the exporter derives each camera's vertical fov from that resolution.
- **Stages:** `stage.<shot>` markers place the figure in each shot. The exporter drops an empty's
  rotation (the furnace README records this too), so the facing direction rides in `loom_dir`
  (glTF).
- **Lamps:** `lamp.head.<car><l|r>`, `lamp.tube.<nn>`, `lamp.back.quad` and `lamp.key.cyc` carry
  `loom_light_kind`, `loom_light_color`, `loom_light_lumens`, `loom_light_cone_deg` and
  `loom_light_dir` (glTF). The haze pass and the headlight projectors read them.
- **The cyc sits at the origin, like the warehouse.** The two are never drawn in the same shot. A
  directional light's shadow volume is framed around the world origin, so a set anywhere else gets
  no shadow.

## Cars

A body is a loft of cross-sections along the car, subdivided twice. The underbody rises over each
axle, which cuts the wheel arches without a boolean. The vertical-bar grille, lamps, turbine wheels
and mirrors are hard-surface pieces. No brand likeness is intended; the proportions are those of the
reference's large luxury SUVs.
